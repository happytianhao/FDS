# 可复用的任务接口草案

这些是本次源码审查后的设计建议，**未作为本次模型消融的输入，也不是已经验证有效的优化提示**。正式使用时，应从允许的训练目标、成功/失败视频和公开接口确认事件定义；不要把隐藏评价器状态或精确判定阈值交给策略。每个模板都应附通用动作坐标系、时钟、标定、观测阶段和错误反馈说明。

“确认”必须指向当前策略可见的证据。没有证据时保留不确定状态，不能把发过的动作自动当作成功。下面的执行顺序是推荐的闭环组织方式，具体接触判据仍需训练样例支持。

## 计数与时机

### BinFill

- **Goal**：本集各颜色的目标数量、目标容器、结束动作。
- **Memory**：按颜色分别保存已确认投入数量；当前手中物体的身份；最近一次投入的证据帧。
- **Execution**：定位所需颜色→确认抓住→搬至容器→释放→检查物体进入目标区域→更新计数。动态来料时每次重新定位。
- **Completion**：所有颜色分别达到目标后再执行终止动作。抓取成功、跨过容器上方和命令返回都不自动计为投入。
- **Recovery**：夹空、掉落、遮挡或投入不明时保持原计数，先收集足以区分结果的观测。

### PickXtimes

- **Goal**：对象身份、重复次数、一次提放包含的物理阶段、结束方式。
- **Memory**：已确认完整周期数，以及当前处于 approach/grasp/lift/place/release/clear 的哪一阶段。
- **Execution**：按阶段推进，放下后释放并移开机械手，以新观测确认物体留在桌面；随后开始下一轮。
- **Completion**：只在完整周期的结束事件得到确认后增加一次；达到次数才按终止按钮。
- **Recovery**：未真正提起、仍被夹持、释放后被带走，都不应推进到下一周期。

### SwingXtimes

- **Goal**：本集先去的侧、下一侧、一次完整往返的定义和次数；目标是否会移动。
- **Memory**：已验证到达序列、已完成往返数、当前下一侧、上次到达证据。
- **Execution**：抓稳并提起→重新定位下一目标→把物体带入训练示例所展示的有效到达区域→检查可见反馈→推进序列。
- **Completion**：到达判据应围绕物体和目标的关系，而非只看 TCP 或发出的坐标；全部事件确认后放下并终止。
- **Recovery**：目标不响应或状态不明时调整/观察，不能继续自述次数。不要把“右侧先行”写死；读取本集 goal。

### StopCube

- **Goal**：数的是哪条边界上的什么穿越事件、目标次数，以及何时触发按钮。
- **Memory**：累计事件、最近运动方向、最近位置和对应仿真时间、速度/周期估计及不确定性。
- **Execution**：先把机械手移到可短程触发的位置；利用连续帧判断过线和运动趋势；将按键动作耗时计入预计接触时刻。
- **Completion**：以实际接触时刻的场景状态为准。模型网络等待不会自动推进该 waypoint 仿真的时间。
- **Recovery**：采样漏掉一次穿越时应标记计数不确定；固定周期和固定提前步数必须有训练依据。

## 遮挡与对象持续性

### VideoUnmask

- **Goal**：需要依次操作的隐藏颜色/身份。
- **Memory**：示范中身份与容器的对应、证据帧、已完成提起顺序。
- **Execution**：从示范提取对应关系→在执行场景定位同一容器→提起→检查实际结果→推进顺序。
- **Completion**：当前看到的容器外观不能替代历史揭示的身份；每个要求的操作均需确认。
- **Recovery**：抓空或提错时保留身份映射，更新动作状态；不要重新按当前位置随意分配颜色。

### ButtonUnmask

- **Goal**：先触发揭示，再按目标身份顺序提起。
- **Memory**：按钮是否已触发、显色关键帧、身份映射、已确认操作列表。
- **Execution**：按按钮并确认触发→及时读取完整显色过程→保存映射→遮挡恢复后按顺序操作。
- **Completion**：每次提起后确认容器和当前目标一致，再更新进度。
- **Recovery**：按钮动作完成不等于已看到有效提示；如果错过提示，不能凭猜测构造映射。

### VideoUnmaskSwap

- **Goal**：示范揭示身份后发生交换，随后操作指定身份。
- **Memory**：稳定对象 ID、隐藏属性、随时间更新的位置、交换前后证据帧。
- **Execution**：先建立映射→连续跟踪交换→保存最终布局→定位当前目标→确认提起。
- **Completion**：按对象身份完成要求；最初位置只是一条历史记录。
- **Recovery**：交叉或遮挡导致对应不确定时保留候选关系和证据，不将位置标签当作永久身份。

### ButtonUnmaskSwap

- **Goal**：按钮揭示身份后经历交换，再按指定顺序操作。
- **Memory**：交互阶段、显色映射、跟踪关键帧、当前身份位置、已完成目标。
- **Execution**：确认触发→记录揭示→跟踪交换→确认交换结束→按当前身份位置执行。
- **Completion**：区分显色结束、交换结束和提起成功这三类事件。
- **Recovery**：如果保留预算有限，应优先保留身份建立与交换交叉帧，而不是均匀保留大量无变化画面。

## 历史引用

### PickHighlight

- **Goal**：提示中被标记的对象及要求顺序。
- **Memory**：提示帧、目标身份、当前估计位置、完成列表。
- **Execution**：触发/观察提示→保存短暂标记的对象→标记消失后重新定位→提起并确认。
- **Completion**：短暂颜色或亮度变化是身份线索，不能把当前未高亮理解为没有目标。
- **Recovery**：不要仅保留最后一张提示结束后的图；若记忆不确定，明确保留不确定性。

### VideoRepick

- **Goal**：示范中的对象身份、要求的重复操作及结束条件。
- **Memory**：目标身份/证据、最新位置、已确认重复数、当前动作阶段。
- **Execution**：从示范选定对象→每轮重新定位→执行完整物理周期→验证后累计。
- **Completion**：相似外观的其他物体不应因为位置更方便而替代目标。
- **Recovery**：身份错误和操作未完成分别处理，不用一次计数更新同时掩盖两种不确定性。

### VideoPlaceButton

- **Goal**：与特定按钮事件相关的示范放置目标。
- **Memory**：按钮事件的时间证据、随后有效放置事件、目标身份及当前位置。
- **Execution**：先做事件时间对齐→识别相关放置→跟踪目标→抓取搬运→释放并离开。
- **Completion**：确认选中的是目标事件对应的放置，而非相邻时间的相似经过。
- **Recovery**：示范事件边界不清时保留其前后帧，不只存一个没有上下文的位置。

### VideoPlaceOrder

- **Goal**：本集要求第几次完整放置，以及应放置哪个物体。
- **Memory**：按顺序确认的放置事件、所选事件的证据、对应目标身份、目标最新位置。
- **Execution**：区分搬运经过与完整放置→选第 k 个事件→更新目标当前位置→抓取→落到目标→释放→退离并检查。
- **Completion**：目标身份、物体释放和最终姿态都需要成立。把物体带到目标上方只是中间状态。
- **Recovery**：当前图不能重建历史次序；历史丢失时不要将最接近的目标当作第 k 个目标。

## 模仿与工具关系

### MoveCube

- **Goal**：示范采用的移动方法及最终关系；本集是否对应已有训练范例。
- **Memory**：方法、初始物体关系、关键过程和约束证据。
- **Execution**：先识别应复现的操作方式→根据当前布局规划→验证每个关键关系→确认终点。
- **Completion**：不能仅到达终点而忽略方法约束，也不能仅复述方法而不检查物体是否真正移动。
- **Recovery**：多种方法分别建模；不把一种训练例的固定位置泛化为全部方法。

### InsertPeg

- **Goal**：示范中的抓取端、插入端、孔/槽、方向关系。
- **Memory**：示范关键关系、工具当前姿态、当前阶段和最近接触证据。
- **Execution**：稳定抓取→确认工具相对夹爪姿态→对齐入口→小步插入→用可见结果验证。
- **Completion**：关注工具端点而非仅 TCP；长度、倾斜和抓取偏移会改变实际接触位置。
- **Recovery**：未对齐、碰撞、滑动分别修正；不要把到达某个手部坐标视作插入成功。

### PatternLock

- **Goal**：有序节点与连线，示范与执行布局是否改变，当前起始姿态。
- **Memory**：节点序列、对应视觉证据、已确认触达的最后节点、当前执行布局。
- **Execution**：先读取当前姿态→安全移动到首节点上方→建立接触→按顺序逐段绘制→观察实际轨迹和节点反馈。
- **Completion**：只有实际触达后才推进索引；不要默认执行时已在首节点，也不要把 TCP 轨迹等同于笔尖轨迹。
- **Recovery**：未触达应调整接触/定位；路线错误与定位偏差要分别判断，不能只反复向下压。

### RouteStick

- **Goal**：示范路线及绕过/穿过障碍的关系；当前棒长与姿态。
- **Memory**：关键路线段、障碍相对关系、已确认通过的段。
- **Execution**：将示范关系映射到当前场景→按当前工具几何检查路径→逐段移动并确认通过。
- **Completion**：检查整个工具与障碍的关系；端点或 TCP 到位不保证杆身无碰撞。
- **Recovery**：工具长度、倾角或布局改变时重算动作；不复制旧世界坐标作为路线定义。

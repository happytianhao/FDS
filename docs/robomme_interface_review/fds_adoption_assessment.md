# 对照现有 FDS：哪些 harness 设计值得采用

核查日期：2026-11-10。本文对照本目录的源码审查、原始实验日志、两组动作干预，以及 E4 的 v028 冻结源码。它是设计评估；本轮没有修改实验代码、启动模型或环境、重跑任何 episode。v028 是候选快照，不能称为已验证的最佳统一版本。

## 判断

最值得采用的是把“事件是什么、证据在哪里、什么时候更新记忆、动作后如何确认”变成执行协议。现有 FDS 已有大量相关提示，缺口主要在协议执行，而非完全没有提醒。

这份研究提供了具体机制证据，但还没有建立“别人的完整 harness 优于 FDS”的公平比较：本机试验采用官方 waypoint 控制器、不同的图像历史和调用预算，也没有完整复现六套模型系统。

## 四项结果能说明什么

| 任务 | 直接记录与干预 | 对 FDS 的启示 | 尚不能据此声称 |
|---|---|---|---|
| PatternLock | full 读对顺序，但第二节点尚未登记便推进；成功轨迹根据未变色反馈修正接触 | 把“发出到达指令”和“观察到触达事件”分开；推进序列需引用新证据 | 删除动力学说明普遍有益；一次通用验证提醒具有稳定收益 |
| VideoPlaceOrder | no_history 首次识别正确，后来丢失目标；固定释放前缀后原地保持 40 步仍 ongoing，执行退离后成功 | 保存目标身份及当前位置；把释放、脱离、最终关系作为不同待核对项 | 所有任务都必须缓存全量原图；任意放置后抬离均足以成功 |
| SwingXtimes | 搬运阶段自述完成十二次到达，评价器记录为零；只将第 4–15 个动作 z 降低 2 cm，最终成功；通用验证提示仍失败 | 必须区分 TCP 到位、物体到位和事件登记；计数应引用事件证据 | 可以在线读取隐藏计数或硬编码高度阈值；旧 FDS 的失败已被证明同源 |
| ButtonUnmask | full 保留显色历史成功；no_history 提错容器 | 将短暂显色证据、稳定身份、当前位置、当前阶段分别保存和关联 | 文本结构化记忆不能替代历史重放；任意稀疏采样都足够 |

两项动作干预均不新增模型调用。Swing 的改变仅限指定动作的 z 分量，但动作耗时随轨迹变化；这是该轨迹的干预证据，不是独立新模型成绩。评价器专用计数与高度判据只用于离线诊断，不能直接进入在线 planner。

本轮直接核对 `probe_evidence.json`：原始 Swing 第 4–15 次动作后的计数均为 0，降低高度后依次为 1–12；原始最终失败，干预最终成功。放置干预中，40 步保持均未成功，随后的原始退离成功。

## 与现有 v028 的具体差距

| 层面 | 现有实现 | 借鉴后应补的机制 |
|---|---|---|
| 物理接口 | 已写坐标系、姿态、夹爪时机、时间推进、IK 限制和实际跟踪反馈 | 保证这些说明与真实后端一致；不要直接复制采用不同控制器的规则 |
| 事件语义 | 已提示计数有效事件、区分 unknown、区分命令与完成 | 为事件建立稳定 ID、状态、时间区间及证据；未确认的尝试不能直接提升为已发生 |
| 记忆 | 已有对象、事件、经验和保留关键帧 | 把身份与位置分开版本化；记录何时更新、哪个后续动作依赖该版本 |
| 行动约束 | 检查引用可用性、契约内部一致性及自报 commitment | selected candidate 绑定具体 tool ID 和规范化参数；不能只依赖 tentative/low-risk 自报标签 |
| 执行后核对 | `execution_verdict` 只评机械拒绝和公开动作错误，语义为 unassessed | 对每项 expected outcome / falsifier 输出 met、violated、unknown 和新证据 |
| 纠错传播 | 已有有限 JSON/契约纠正、上次物理契约跨辅助调用传递 | 假设变化后使旧版本依赖失效，重新核对计数、身份和未执行计划 |

源码证据：

- v028 contracts.py（本地归档：`runs/robomme_plus/task_harness/e4_astra_medium_adaptive_train/versions/v028/src/fds/task_harness/contracts.py`） 已包含 `count_sensitive_actions`、`completion_evidence`、`identity_continuity`、`stalled_progress` 等规则。
- v028 fds.py（本地归档：`runs/robomme_plus/task_harness/e4_astra_medium_adaptive_train/versions/v028/src/fds/task_harness/fds.py`） 中 `execution_verdict(contract, receipts)` 不逐项使用预期结果与 falsifier；`supported` 仍为模型声明。
- 更完整的协议缺口及离线探针见 [FDS 机制边界核查](../fds_mechanism_boundary_review.md)。

因此，再增加一段“请验证”不能补齐以上链条。模型把用词改成 verified，仍可能引用错误的物理判据。

## 六套方法分别借什么

- **Embodied-Astra**：从实际控制后端出发生成准确、精简的世界规则。其官方 waypoint 使用 world xyz+rpy，先移动后施加夹爪；FDS 使用 base xyz+quaternion，夹爪在原始目标开始时生效。照搬动作提示会造成语义错误。
- **3-tier Astra**：把“指令已下达”与“子目标已完成”分开。可以借完成监测的职责划分；不直接移植额外模型、学习型动作执行器或任务专用触发规则，也不剥夺模型自行 finish 的权利。
- **MEMI**：让每个记忆字段说明保留什么、何时更新、行动如何使用；下一周期显式携带。其使用字段自报仍非因果证明；离线优化过的任务记忆规则属于额外训练知识。带 oracle skill 的分支不适用于本项目的空 skills 条件。
- **PonderPounce**：保存当前子目标、观察时间、适用时段和未决问题。时间旧不等于事实失效：历史显色可以长久有效，目标当前坐标则会随移动失效。
- **SimpleMemVLA**：借带时间的多模态上下文和清楚的机器人状态；学习型动作头不是直接可替换的提示模块。
- **FrameSamp+Modul**：借鉴针对事件保存历史信息的思想。学习型特征采样和动作条件化需要训练，不能将 prompt 调整称为复现。

## 图像与预算对照不能省略

| 项目 | 本机 waypoint 接口试验 | FDS E4 |
|---|---|---|
| 首轮 PatternLock | 71 张 front + 1 张当前 wrist | 34 张图片，包含两相机 |
| 首轮 VideoPlaceOrder | 439 张 front + 1 张当前 wrist | 34 张图片，包含两相机 |
| 历史 | 每次请求显式重放保留的观测与公开回答，受总图像上限限制 | 当前观测、有限保留关键帧、结构化 memory 和反馈；没有全量对话重放 |
| 后续观察 | 动作后按 stride 采样 front，附当前 wrist | 动作批次结束后提供选定中间帧与最终帧；中途不能因图像自动停下重规划 |
| 调用上限 | 40；回答直接给 waypoint | 100；几何辅助、回看、纠正也计入 |
| 控制 | 官方 waypoint | 自定义 TCP/IK 与关节插值 |

`sparse16` 是每 **16 帧**取一次 front，再附最后帧；不是最多给 16 张图。`no_history` 同时移除旧图像与旧回答，也没有以 FDS 的结构化 memory 替代，不能当作“全量历史 vs FDS memory”的比较。

本轮额外核对四项任务的 E4 首次尝试与接口 full：官方 seed 相同；首轮共有源索引上的图片分别为 PatternLock 5 张、VideoPlaceOrder 8 张、SwingXtimes 2 张、ButtonUnmask 2 张，文件 SHA256 全部一致。恢复运行的首轮图片引用原中断目录，因此应沿 exchange.jsonl 的原始路径核对。相同初始场景并不消除后续控制、观察和预算差异。

本机 A100 支持这些试验的仿真与渲染，不能解释为在本机运行了 Astra 权重。

## 建议的最小改动顺序（尚未实施）

1. **先绑定行动和声明。** 统一 action plan 与 tool ID，保存 requested/resolved/executed 参数。把假设与事件赋予稳定 ID 和 revision，让候选引用具体版本。这能机械审计，但不能证明视觉关系正确。
2. **在下一次正常 planner 调用中先做后验核对。** 每个预期事件返回 met/violated/unknown、公开新证据及需修正的 memory/assumption ID，再决定下一步。确定性公开反馈可由宿主核对；视觉判断明确标为 model_assessed，不能包装成独立视觉证明。复用现有调用预算。
3. **按依赖保留证据。** 在现有图像预算内优先保存未决、仍被后续动作依赖的证据，并显示 review window 即将过期。超出保留容量时暴露冲突；不能静默删除又继续将结论当作已验证。扩大图像容量另做实验因素。
4. **处理证据不足和纠正停滞。** 允许有界的取证/纠正动作，禁止把辅助工具的数值输出冒充身份、接触或成功证明。若重复调用没有新证据，也没有区分假设的作用，应合并或停止；不能把所有几何调用、回看一律删掉。无法辨别时保留 unknown，由模型选择继续探索或诚实 finish。

不能用“没有公开可观测证据”伪造一个完成检测器。对于 Swing 这类物理事件，若公开反馈不能直接区分，需承认不确定性，并设计基于公开任务语义和观测的辨别动作。隐藏的 `swing_count` 和高度阈值只能留在诊断侧。

16 类 task contract 是设计草案，并未注入当前这 16 个主实验。直接导入每任务规则，即使技能列表仍为空，也引入了任务专用先验。若采用，应作为单独条件；控制器替换、全历史重放、增加图像预算、独立模型检查器也应单独立项，不能与 FDS 改动一起记成同一收益。

## 如何验证确实改善

在固定同一 harness、模型、memory、空 skills、工具、图像预算、episode/seed 和总调用预算下，比较：普通闭环 → 仅记录契约 → 执行前约束 → 加入逐项后验核对；另设相同预算的普通条件检查/验证重规划控制。普通对照也应保留可用的基础闭环能力，不能人为移除正常反馈制造弱基线。

先用既有日志离线检查动作绑定、事件重复计数、证据过期和依赖失效，再在另行确定的训练评估安排下进行冻结版本比较。既有 episode 的最多三次及特批第四次上限仍有效；不能借设计评估自行增加尝试。

除 success，还应记录：无证据的状态提升、带未决依赖的承诺行动、纠正后恢复、重复辅助调用、事件确认延迟、图像量、prompt/completion token 和环境步数。反复用同一训练轨迹开发和评估会产生适应性偏差，应明确报告，不能将累积 best-of 成绩作为统一版本表现。
